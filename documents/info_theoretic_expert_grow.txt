================================================================================
 Information-theoretic tools for expert growth (Dynamic Tree MoE)
================================================================================

Motivation
----------
Every leaf expert has the SAME parameter count, so each leaf has roughly the
same learning capacity C. Harder local problems need more capacity than one
expert can provide. Growth = allocate extra capacity by splitting a leaf into
children under a new router.


1. Quantities
-------------
For one attribute head (opacity / cov / color):

  Y   : target / residual the expert should predict
  X   : anchor features
  ℓ   : leaf (expert region)
  p(ℓ): traffic mass (soft-gate average)          ≈ mass_frac
  L_ℓ : mean training loss on leaf ℓ              ≈ proxy for H(Y|ℓ)
  feat_var_ℓ : feature variance on leaf           ≈ proxy for H(X|ℓ)


2. Difficulty = conditional entropy
-----------------------------------
Ideal:

  H(Y | ℓ)  = E_{x ~ p(x|ℓ)} [ H(Y | X=x, ℓ) ]

High H(Y|ℓ)  → leaf still uncertain → grow candidate
Low  H(Y|ℓ)  → leaf already fits its region → do not grow

Proxy in code: leaf loss L_ℓ.


3. Is a split worth it?  Mutual information gain
------------------------------------------------
Split ℓ → children c ∈ {1,2}. Information gain:

  ΔI = I(Y ; child | ℓ)
     = H(Y|ℓ) − Σ_c p(c|ℓ) H(Y|c)

Large ΔI → split reduces uncertainty → GROW
ΔI ≈ 0  → fake grow (routing churn only) → SKIP  (stump failure mode)

Train-time proxy after a split / short dense window:

  ΔÎ_ℓ ≈ L_ℓ − Σ_c w_c L_c


4. Capacity–difficulty mismatch (core rule)
-------------------------------------------
Equal params ⇒ fixed per-leaf capacity C.
Local difficulty R_ℓ ≈ H(Y|ℓ) ≈ L_ℓ.

Grow leaf ℓ iff ALL hold:

  (1) R_ℓ  >  C_eff                 # harder than one expert can learn
  (2) p(ℓ) ≥ p_min                  # enough traffic to justify capacity
  (3) ΔÎ_ℓ > τ                      # split actually reduces uncertainty

Calibrate capacity from current leaves, e.g.

  C_eff = κ · median_ℓ (L_ℓ),   κ ∈ [1.1, 1.3]


5. Load entropy / effective experts (sanity check)
--------------------------------------------------
  H_load = − Σ_ℓ ḡ_ℓ log ḡ_ℓ
  N_eff  = exp(H_load)

Local neff (in code) ≈ diversity inside a leaf.
  High H(Y|ℓ) + high mass → structure bottleneck → grow THAT leaf
  High mass + low H(Y|ℓ)  → popular, not hard → do not grow


6. Mapping to current growth score S_ℓ
--------------------------------------
Current (approximate) score:

  S_ℓ = mass_frac · (1 + 1.5·feat_var) · (1 + L_ℓ / median L)

This estimates: busy × heterogeneous × high-loss.
IT upgrade: keep S_ℓ for ranking, but gate with (1)–(3) above,
especially require ΔÎ > τ so outdoor/stump does not over-grow.


7. Ideal vs bad growth
----------------------
Ideal tree:
  - start with 4 equal-capacity leaves
  - split only leaves with R_ℓ > C and ΔÎ > τ (often color head)
  - end with ~5–6 leaves; easy regions stay unsplit

Bad (stump-like):
  - grow because one leaf has ~30% mass
  - high appearance variance but ΔÎ ≈ 0
  - capacity spent on wrong head/node → PSNR drop


8. One-line summary
-------------------
Equal expert size = fixed capacity C.
Use H(Y|ℓ) for difficulty, p(ℓ) for worth, ΔI for verified gain.
Grow only when difficulty exceeds capacity AND the split reduces entropy.
